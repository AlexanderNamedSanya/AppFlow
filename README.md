# AppFlow

Минималистичная автоматизация Windows на C# / .NET 10, WPF и [WPF UI](https://wpfui.lepo.co/). Без регистрации, облака и телеметрии приложения.

Версии используют формат `YY.MM.Version`: год, месяц и номер выпуска за месяц (например, `26.11.1`). Текущая версия сборки отображается в левом нижнем углу окна.

## Запуск

Скачать готовый EXE и архив исходников: [GitHub Releases](https://github.com/AlexanderNamedSanya/AppFlow/releases/latest). Каждый релиз содержит оба файла. Публикация тега `v<версия>` автоматически собирает EXE и прикладывает исходники этого же коммита; версия тега должна совпадать с версией проекта.

Готовая самостоятельная сборка: `artifacts/win-x64/AppFlow.exe`. .NET отдельно устанавливать не требуется. Переносите EXE в постоянную папку **до** включения автозапуска. Windows 10/11 x64; ARM64 можно собрать отдельно.

1. Нажмите **+** в левой панели или в центре пустого окна. В открывшемся окне выберите установленное приложение из списка с поиском либо нажмите **Обзор…** для выбора конкретного EXE. Список собирается из меню «Пуск», App Paths, системного каталога AppsFolder (включая Microsoft Store) и списка установленных программ Windows (для текущего пользователя и всего компьютера, 32/64 бит).
2. Нажмите **Добавить действие**. В том же окне выберите установленную программу, EXE через **Обзор…**, сайт вводом адреса в общее поисковое поле или скрипт через **Скрипт…** справа от «Обзор». Если Windows не сообщает путь к EXE, нажмите **Выбрать EXE…**. Для Steam и других лаунчеров выбирайте EXE игры, не Steam и не ярлык. Для приложений Store путь определяется по манифесту пакета, а запуск использует системную активацию приложения; если путь недоступен, приложение остаётся в списке с возможностью выбрать EXE. Работающее Store-приложение распознаётся по системному идентификатору приложения, даже если в манифесте указан загрузчик обновлений. Владение после активации сохраняется за исходным экземпляром и его проверенными процессами-потомками того же приложения, включая переход от загрузчика к рабочему EXE (например, RIFT). При завершении проверяются PID, время создания и реальный путь каждого такого процесса; независимые и ранее открытые экземпляры не присваиваются.
3. Раскройте карточку: внутри находится список строк **событие основной программы → действие дочерней программы [опции]**. Добавляйте строки кнопкой **+ Событие**, удаляйте кнопкой **×**. Клик по строке события раскрывает или скрывает настройки; при наведении строка подсвечивается. Списки события и действия, а также кнопка удаления работают независимо. Для события **Работает** доступно только действие **Циклично**, с настройками времени работы и паузы. У остальных событий опции новых строк выключены. Время указано в секундах.
4. Все изменения применяются и сохраняются автоматически после короткой паузы во вводе, включая добавление, отключение и удаление связей и общие настройки. При неполном или неверном времени продолжают действовать последние корректные правила; ошибка отображается в окне. Перед выходом ожидающие изменения сохраняются. Уже работающие основные программы синхронизируются автоматически.

В свёрнутой карточке показана одна общая строка: события запуска → действия во время работы → события выхода. Все действия одной фазы идут подряд в порядке настройки. Цепочка выровнена по центру. Используются иконки основной и дочерней программ со значками действий; названия программ и подписи «запуск» / «закрытие» под иконками не выводятся. Полные названия и действия доступны в подсказках. Для цикла показано только время работы / паузы, например **1 мин / 5 мин**, для таймера — **3 минуты**. Отсутствующие события и выключенные опции не добавляются. При раскрытии карточки превью скрывается и появляется редактор событий. При запуске основной программы или выполнении действия соответствующий значок кратко увеличивается; при закрытии — уменьшается и затухает, затем возвращается в исходное состояние. Фазы цикла и таймерное закрытие анимируются по фактическому выполнению. Пропущенные и неудавшиеся действия не показываются как выполненные. Анимация учитывает системное отключение анимаций Windows.

Справа в карточках основных и дочерних программ доступна кнопка **▶ Запустить** (название отображается в подсказке). Кнопка прозрачная, с лёгкой подсветкой при наведении. Уже работающая программа повторно не запускается. Ручной запуск считается пользовательским: автоматизация не получает право завершать этот экземпляр. Ручной запуск основной программы активирует её сохранённые события обычным способом.

При добавлении дочерней программы или скрипта создаются две строки: **Основная программа запущена → запустить/выполнить** и **Основная программа закрыта → закрыть/остановить**. Все опции изначально выключены. Событие закрытия управляет тем же экземпляром дочерней программы или интерпретатора, который запустило событие открытия этой связи. Если нужна только реакция на запуск, удалите строку закрытия.

Программы и сайты добавляются через одно поисковое поле без переключения режимов. Введите название программы или адрес сайта (например, example.com): сайт появится в списке с иконкой глобуса и именем домена. По умолчанию добавляется только открытие при запуске основной программы. Можно выбрать другое событие и задержку. Страница открывается в браузере по умолчанию; AppFlow не получает права закрывать браузер или его вкладки. Таймер завершения и цикл для сайта не предлагаются.

Кнопка **Скрипт…** справа от **Обзор…** открывает простой текстовый редактор: задайте название, выберите PowerShell, CMD или BAT и введите код. Кнопка **Добавить** создаёт отдельный файл в папке `scripts` рядом с конфигурацией и добавляет действие; скрипт при этом не запускается. Поддерживаются многострочный ввод и табуляция. Скрипты `.ps1`, `.bat`, `.cmd` выполняются в фоне с рабочей папкой скрипта. PowerShell запускается через Windows PowerShell с `-File`, без профиля и без изменения политики выполнения. Пакетные файлы запускаются через `cmd /d /s /v:off /c`; пути с пробелами и `&` поддерживаются. Перед запуском проверяются уже известные экземпляры и обычные вызовы `powershell/pwsh -File` либо `cmd /c` через WMI. Уже работающий пользовательский скрипт не присваивается. Остановка и таймеры затрагивают только проверенный процесс интерпретатора AppFlow; запущенные скриптом дочерние приложения не завершаются деревом.

Для сценария TESO → TTC Client включите в опциях запуска **Закрыть через 180 с**. Таймер закрывает TTC по своему сроку, даже если TESO уже завершилась. Чтобы закрывать TTC сразу при выходе TESO, нужна отдельная строка **Основная программа закрыта → закрыть**. Неявного закрытия при выходе основной программы нет. Если TTC запущен вне AppFlow, ни одно событие его не закроет.

Событие **Основная программа работает** активируется и для уже запущенной основной программы при старте AppFlow. Единственное действие — **Циклично**. В опциях задайте время работы дочерней программы и паузу после закрытия; отдельного переключателя цикла нет. Например, работа 60 с и пауза 300 с: запуск → работа 60 с → закрытие → пауза 300 с → новый запуск. Время каждой фазы — от 1 до 604800 секунд. При закрытии основной программы новые циклы и ожидающие запуски отменяются. Текущая фаза работы завершается по своему таймеру; для немедленного закрытия нужна отдельная строка события выхода. Оставшийся таймер проверяет принадлежность исходного экземпляра и не закрывает новый экземпляр, запущенный другим событием. Чужой экземпляр не затрагивается. Для сайтов событие **Работает** недоступно.

В **Настройках** доступны только автозапуск, системная/светлая/тёмная тема и поведение закрытия окна. При сворачивании в трей мониторинг продолжается; двойной щелчок открывает окно, меню значка позволяет выйти. Повторный запуск AppFlow открывает существующее окно.

Оформление следует Windows 11: системный материал Mica в навигации и заголовке, отдельный слой содержимого, Fluent-карточки, системный акцент и переключатели. Mica учитывает настройки прозрачности Windows; при отсутствии поддержки используется обычный фон. Светлая и тёмная темы применяются ко всем экранам.

## Безопасность процессов

### Обучение штатному выходу

В раскрытой карточке дочерней программы нажмите **Обучить закрытию**. Откроется небольшое квадратное окно с индикатором: наблюдение начинается автоматически. Для сайтов и скриптов обучение не предлагается.

1. Если программа не работает, нажмите **Запустить <название>**. Дождитесь подписи **Закройте программу вручную** и завершите её обычным способом. Окна и меню во время обучения можно открывать.
2. После записи появятся **Завершить обучение** и **Добавить способ закрытия**. Вторая кнопка возвращает к наблюдению; все ранее записанные способы остаются в текущем обучении. Можно показать выход из окна, меню или трея без ручного выбора вида проверки.
3. Нажмите **Завершить обучение**. AppFlow самостоятельно запустит программу для проверки каждого нового способа: сначала проверит фоновую команду, при необходимости — записанный выход через трей или из открытого окна. Во время проверки программа может появляться и закрываться. После проверки окно обучения закроется; результат появится в основном окне AppFlow.

Сохраняются только способы с подтверждённым выходом и совпадающим кодом завершения. Ранее сохранённые способы не теряются; все новые успешно проверенные способы добавляются одной записью. Посторонние экземпляры не используются для автоматических тестов. Если отправленная команда ещё не завершила программу, новые запросы ей не посылаются, а непроверенные способы не объявляются успешными. Закрытие окна крестиком отменяет текущую запись или проверку без сохранения незавершённой сессии.

При наличии сохранённых и проверенных способов из обучения закрытие выполняется в порядке: фоновая команда → способ для уже открытого окна → способ через трей. Если обучение не пройдено, не удалось или после обновления EXE нет подходящего способа, AppFlow принудительно завершает собственный проверенный процесс. После подтверждённого выхода действия связи продолжаются. Несохранённые данные при принудительном завершении могут потеряться. Автоматический поиск команды «Выход» без обучения не выполняется. AppFlow не разворачивает скрытое основное окно. При работе через трей меню может кратко появиться; пункт выбирается сразу после обнаружения. Если значок скрыт, допускается краткое открытие области скрытых значков. Положение курсора восстанавливается, если пользователь не успел его переместить. Координаты кликов не сохраняются: значок и команда находятся заново. При неоднозначном совпадении действие не выполняется.

Если пользователь работает с меню, открыл скрытые значки трея, удерживает клавиши/кнопки или недавно вводил данные, воспроизведение через трей откладывается. Новое движение мыши или нажатие клавиши во время попытки отменяет дальнейшие действия; AppFlow не возвращает фокус и курсор и не закрывает пользовательский трей после такого вмешательства. Временное препятствие не отменяет запрос закрытия: повторные попытки идут через 2, 4, 8 и затем не чаще одного раза в 15 секунд. Другая дочерняя программа продолжает обрабатываться отдельно. Повтор относится только к исходному экземпляру; перезапуск основной программы отменяет ожидающее закрытие по её предыдущему выходу. Если команда выхода уже отправлена, повторно она не посылается: AppFlow ожидает завершения.

Во время обучения запуски и закрытия этой программы приостановлены, остальные связи продолжают работать. После закрытия окна обучения таймеры продолжаются с оставшегося времени. Пользовательский экземпляр, выбранный для обучения или проверки, не становится собственностью автоматизации.

Способы хранятся отдельно в `%LOCALAPPDATA%\AppFlow\close-profiles.json` и привязаны к пути и содержимому EXE. После обновления программы старый способ не используется без повторного обучения. Можно записать несколько способов за одно обучение; уже сохранённые способы дополняются новыми проверенными вариантами. Нестандартные меню, меняющиеся идентификаторы и недоступный интерфейс могут потребовать другого способа обучения; неподтверждённый выход не объявляется успешным.

### Владение и завершение

- Проверка полного пути к EXE перед каждым запуском. Повторный запуск работающей программы пропускается.
- Владение устанавливается только для процесса, созданного AppFlow: PID + время создания Windows + полный путь.
- Перед закрытием экземпляр проверяется заново. Один kernel handle удерживается до конца закрытия, PID другого экземпляра не даёт права на завершение.
- Приложения закрываются обученным способом, привязанным к текущему содержимому EXE. Без подходящего способа AppFlow принудительно завершает собственный проверенный процесс без дочернего дерева, дожидается его выхода и продолжает связь. Системные команды закрытия окна, WM_CLOSE и Restart Manager не используются.
- После воспроизведения обученной команды AppFlow ожидает до 30 секунд на сохранение и выход. Модальные диалоги автоматически не подтверждаются. Недоступный способ без сохранённого варианта через трей и таймаут после отправки команды приостанавливают связь; программа остаётся работать. Неудачная попытка воспроизведения через трей повторяется автоматически. Цикл продолжает следующие действия только после подтверждённого выхода. Для проверенной группы Store-процессов используется общий срок ожидания.
- Остановка скрипта принудительно завершает только собственный проверенный интерпретатор без дочернего дерева. Отмена ожидания и выход из AppFlow прекращают дальнейшие запросы закрытия; уже отправленную команду программа может выполнить.
- Если Windows запрещает доступ к процессу, AppFlow сообщает об ошибке и приостанавливает действия связи; обхода системных прав нет. Повышенным приложениям могут потребоваться такие же права у AppFlow. Чужие экземпляры, в том числе при повторном использовании PID, не закрываются.
- Общая программа остаётся работать, пока у неё есть активные связи. Отключение, изменение и удаление применённого правила освобождает его владение; последнее владение закрывает программу. Сохранение неизменённых правил не сбрасывает таймеры.
- Выход из AppFlow оставляет запущенные программы работать. После перезапуска они считаются внешними: AppFlow не восстанавливает права на завершение по старому PID.
- Если программа завершилась сама, владение снимается. Новый запуск происходит только по следующему событию или настроенному повтору.

Настройки хранятся в `%LOCALAPPDATA%\AppFlow\configuration.json`, запись заменяет файл атомарно. Повреждённый файл сохраняется рядом с суффиксом `.invalid-<дата>`; ошибка показывается в окне.

## Сборка и тесты

Нужен .NET 10 SDK под Windows. Visual Studio не обязателен.

```powershell
dotnet build AppFlow.slnx
dotnet test tests/AppFlow.Tests/AppFlow.Tests.csproj
dotnet run --project src/AppFlow.Desktop
./scripts/publish.ps1
# ARM64:
./scripts/publish.ps1 -Runtime win-arm64
```

В этой рабочей папке SDK также установлен локально: `.tools/dotnet/dotnet.exe`. Для запуска через него установите `$env:DOTNET_ROOT = "$PWD\.tools\dotnet"`; зависимости восстановлены в `.tools/packages`.

Иконка AppFlow хранится в `src/AppFlow.Desktop/Assets/AppFlow.png`. Один знак используется для EXE, панели задач, трея, заголовков всех окон и стартового экрана. После изменения PNG запустите `./scripts/update-icon.ps1`, чтобы обновить ICO с размерами 16–256 пикселей, затем пересоберите приложение.

Тесты проверяют таймеры на виртуальных часах, ранний выход, чужие процессы, повтор PID, самостоятельный выход, повторные события, конкурентные вызовы, общие связи, несколько экземпляров основной программы, изменение правил, JSON и настоящий выделенный процесс Windows. Пользовательские программы в тестах не запускаются и не завершаются.

Проверки закрытия на выделенных тестовых EXE охватывают запись и проверку обученного способа, воспроизведение из окна и трея, привязку к версии EXE, защиту чужих экземпляров и принудительное завершение без обучения и без старых запросов закрытия. Тесты движка проверяют таймеры, циклы, продолжение после подтверждённого принудительного выхода, приостановку при отказе, отсутствие повторных уведомлений при неизменном состоянии и ожидание без опроса при пустой конфигурации.

Проверки вмешательства пользователя открывают отдельное тестовое меню и имитируют конкурирующий ввод: существующее меню сохраняется, выход откладывается и успешно повторяется после освобождения трея. Отдельно проверяются две дочерние программы, паузы повторов, сохранение шага цикла, отмена при перезапуске основной программы и защита нового экземпляра.

## Потребление ресурсов

Основные программы проверяются одним нативным обходом процессов с фильтром по именам; полный путь читается только у подходящих кандидатов. Дочерние процессы проверяются по сохранённой идентичности. Неизменившийся статус не создаёт повторные снимки для интерфейса и задания диспетчера WPF. При пустой конфигурации монитор ждёт изменения без секундного таймера. При запуске с `--background` главное окно создаётся только при открытии из трея. Частота проверки настроенных программ сохранена: примерно раз в секунду.

## Структура

- `src/AppFlow.Core` — модели, проверка конфигурации, JSON-хранилище, последовательный асинхронный движок и договор работы с процессами.
- `src/AppFlow.Desktop` — MVVM, WPF UI, Windows API, иконки EXE, трей, автозапуск, темы, mutex и локальный канал активации второго запуска.
- `tests` — тесты движка/хранения/Windows API и отдельный тестовый EXE.

## Ограничения первой версии

- Мониторинг Windows API выполняется раз в секунду. Процессы короче одного интервала могут быть пропущены; действия выполняются с точностью примерно в секунду. Несколько экземпляров одной основной программы считаются одной активной программой до выхода последнего.
- Запуск определяется по полному пути независимо от лаунчера. Если связанный EXE сам является лаунчером, AppFlow владеет только им; дочерний процесс не присваивается. Выберите EXE самого клиента.
- Список установленных программ предназначен для приложений с обычными EXE. Некоторые игры, portable-программы и приложения Microsoft Store могут отсутствовать или требовать выбора файла вручную. Команды удаления и запуска ярлыков при поиске не выполняются.
- AppFlow работает с текущими правами пользователя. Для повышенных/защищённых процессов доступ может быть запрещён; ошибка отображается, чужие процессы не завершаются. Между проверкой и запуском внешний лаунчер теоретически может одновременно запустить второй экземпляр; сериализация защищает от дублей внутри AppFlow.
- При изменении EXE или скрипта на диске/переносе файла удалите старую запись и выберите новый файл. Аргументы командной строки и группировка правил не предусмотрены.
- Поддерживаются скрипты Windows `.ps1`, `.bat`, `.cmd`. Для PowerShell действуют системные права и политика выполнения. Для `.bat/.cmd` путь с символом `%` отклоняется, чтобы исключить подстановку переменных в имени файла. Скрипты, вызванные внутри уже открытой интерактивной консоли или сложной команды, могут не распознаваться до повторного запуска; AppFlow не завершает такие неизвестные экземпляры.
- Автозапуск через HKCU Run включается только настройкой пользователя. Перенос AppFlow после включения автозапуска требует выключить и снова включить настройку.

Для изолированной проверки можно передать `--data-dir <папка>`. `--background` запускает в трее, `--exit` завершает текущий экземпляр AppFlow. Эти параметры не нужны для обычной работы.
